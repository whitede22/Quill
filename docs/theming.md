# 界面主题：一套主题 = 一份完整调色板（Round 26）

## 一、六套主题

| id | 名字 | 底座 | 强调色 |
|---|---|---|---|
| `ink` | 靛蓝（默认） | 浅色 | `#4A6FA5` |
| `sage` | 松绿 | 浅色 | `#3F7A63` |
| `clay` | 赭石 | 浅色 | `#8C5A33` |
| `plum` | 绛紫 | 浅色 | `#7A4A72` |
| `graphite` | 石墨 | 浅色 | `#5A5F66` |
| `night` | 夜 | **深色** | `#7FA6DC` |

前五套换的是**强调色与它的几个派生色**（悬停、柔和底、卡片悬停、禁用态），底色共用同一份；
`night` 换的是**整份底座**——正文、次要文字、边框、提示条、滚动条把手全部另挑了一份。
顺序即设置界面下拉框的顺序，第一条是默认。

## 二、结构：两份底座 × 一份强调色族

```
_BASE_LIGHT / _BASE_DARK      ← 底色、正文、次要文字、边框、提示条、滚动条……
_ACCENTS                      ← 每套主题真正不同的那部分 + 它的显示名
THEMES = { ...合并... }        ← 唯一一处组装
```

`THEMES` **只能有这一处组装**。在别处再拼一次，代价不是"重复了几行"，而是「加了新键、
只在一边加」不会报错，只会让某套主题悄悄少一个字段、某一块没上色。

`_TEMPLATE_KEYS` 是样式表模板里所有 `$name` 的白名单，`stylesheet()` 用它从调色板取值。
**它的作用是护栏**：加了新颜色却忘了补某套主题，会在生成样式表时直接 `KeyError`，
而不是渲染出一块没有颜色规则的控件。selfcheck 里另有一条断言：每套主题都必须补齐
模板需要的全部颜色。

## 三、样式表里不允许出现字面颜色，界面代码里也不允许

### 模板侧

早先 `#primary:disabled`、破坏性悬停、滚动条把手这几处写死了十六进制色。换成第二套主题时
它们**不报错**，只是静静地留着上一套主题的颜色，看起来像「主题换了一半」。
现在模板里一个字面颜色都没有，全部来自调色板。

### 界面代码侧（这一轮补的）

上面那条只管得住模板，真实的洞在别处。**这是一次真事故**：

```
app/ui/widgets.py（修复前）
    parts.append(f"<span style='color:#1F1F1E'>{syn.gloss_zh}</span>")
    parts.append(f"<span style='color:#8A8A86'>{syn.diff_note}</span>")
```

这两个值正是**浅色主题**的 `text` / `text2`。深色主题的卡片底色是 `#24262A`，
中文简释压上去的对比度是 **1.09:1** ——不是"偏淡"，是**整行看不见**。它不报错、
不影响任何断言，只是让一排释义消失。

修法是把那一行拆成两个 `QLabel`（`#synGloss` / `#synNote`），颜色交给样式表按
objectName 给。拆成两个标签而不是继续拼富文本，是因为**一个 QLabel 只有一个 color**：
要让释义比差异说明重一档，就只能往里塞字面颜色。

修完之后逐套量过（解析后颜色 vs 调色板）：

| 主题 | 卡片底色 | 简释 `#synGloss` | 差异说明 `#synNote` |
|---|---|---|---|
| `ink` | `#FFFFFF` | `#1F1F1E`　16.50:1 | `#8A8A86`　3.47:1 |
| `night` | `#24262A` | `#E8E8E6`　**12.35:1** | `#A8A8A4`　**6.35:1** |

于是现在的判据有两条，缺一不可：

1. **selfcheck**：扫描 `app/ui/*.py`（`theme.py` 除外），不许出现 `#RRGGBB`。
2. **gui_smoke**：逐套主题读 `#synGloss` / `#synNote` 的**解析后颜色**，与调色板对表。

### 为什么扫描要「去掉注释」

扫描必须只看代码。注释里出现 `#1F1F1E` 是在**解释**一个颜色（比如"这个色值在深色主题下
只有 1.09:1"），不是在用它。把注释也算进去，就会让「记录这个坑」和「重新踩这个坑」变成
同一件事——于是文档里再也写不出具体色值，而那恰恰是排查时最需要的信息。

所以扫描前先用 `tokenize` 去掉 Python 注释、用正则去掉 QSS 的 `/* ... */`，
**字符串必须留着**：写死的颜色最常出现的地方正是字符串（富文本片段、样式串）。
判据本身自证过六种形态：干净文件不误报、喂进修复前那段代码能报出 `#1F1F1E`/`#8A8A86`、
纯注释不误报、字符串里的色值必报、QSS 注释不误报、QSS 声明必报。

## 四、深浅两套底座：「背景透出」的档位值必须分家

档位是「面板铺自身底色的不透明度」。可读性的**最坏情况在两边是相反的**：

- 浅色主题：正文是深色，最坏是背景图那块**纯黑**——面板被压暗。
- 深色主题：正文是浅色，最坏是背景图那块**纯白**——面板被提亮。

同一个 58% 在浅色下守住 5.4:1，在深色下只剩 3.2:1（跌破 4.5）。因此：

| 档位 | 浅色底座 | 深色底座 |
|---|---|---|
| `soft` | 88% | 96% |
| `medium`（默认） | 72% | 84% |
| `bold` | 58% | 72% |

档位**名**在两边共用（用户选的是一件事），档位**值**按底座分家（实现上必须不同）。
`veil_level()` 只归一档位名，不需要主题参数——正因为名是共用的。

断言两条，成对存在：每套主题每个档位的最坏情况正文对比度 ≥ 4.5:1；**并且**再降 15 个百分点
必跌破（否则说明这个"下限"不是真的下限，规则可以更松）。

## 五、哪些文字会跟着档位换加强色

面板半透明之后，**直接压在面板上**的次要文字（备注、音标、小节标题、占位提示）会跟透上来的
背景融在一起。所以最透那一档给它们换一档更深的颜色（`text2_strong` / `text3_strong`），
soft / medium 原样不动——动它们只会无端把「淡 + 细」的层次压平。

`_STRONG_TEXT` 存的是**完整选择器**，不再是 objectName 现拼的 `QLabel#{name}`：
面板上还有一种「自己不带底色」的组件，把选择器写死成 QLabel 就永远加不进它。

**`QPushButton#bare` 刻意不在加强色的名单里**，它的解法是垫底：

> 工具栏那三个无边框按钮（格式说明 / 备份 / 设置）与左栏底部的计数标签
> （`QLabel#countLabel`）既不在面板里，也没有列表那样的轨道衬底，配了背景图之后
> 它们的字**直接压在原图上**。
>
> 换一个更深的文字色救不了：浅色主题的次要文字 `#8A8A86`（相对亮度 0.253）压在一张
> 中间调的图上，对比度趋近 **1:1**；而换成深色，同一段字落到图上偏暗的那一块又同样
> 看不见。**一个颜色救不了两种背景，只能给文字一个受控的表面。**
>
> 这正是状态栏当初的结论——它早先设成 `transparent`，后来改成带 alpha 的底。
> 当时只改了状态栏那一处，别处照旧裸着；这一轮把另外两处补齐，不透明度沿用
> **面板那一档**（同一屏里两处文字的可读性该由同一个规则决定，各调各的会让
> 「档位」这个概念失去意义）。

## 六、设置的即时预览与取消还原

- **即时生效**：配色是「看着挑」的，要用户先保存、看一眼、再打开设置改，等于让他来回跑三趟。
- **取消必须还原**：用户试了几套之后按取消，若什么都不做，界面会停在他最后试的那套上，
  而配置里存的仍是原来那套——重启又变回去。「看到的」与「存下来的」不一致，是这套界面里
  最不该出现的东西。
- 回调 `on_theme_preview=None` 时退化成「保存后才生效」，于是自检 / 截图脚本沿用旧调用
  方式也不会坏。

## 七、验证方式一览

| 层 | 守什么 |
|---|---|
| selfcheck | 逐套主题逐对（文字 / 底色）算对比度 ≥ 4.5:1；每档最坏情况 ≥ 4.5:1 **且**再降 15 个百分点必跌破；模板与 `app/ui` 里都没有字面颜色；每套主题都补齐模板需要的键；不认识的主题名一律退回默认 |
| gui_smoke | 逐套读主按钮底色与窗口底色对表调色板；即时预览 / 取消还原；最透档 vs 适中档的小节文字色；**同义语两行取色逐套对表** |
| 消融 | A18 主题换色、A19 取消设置还原主题、A21 最透档的文字加强色 |
| 变异 | 样式表忽略主题参数、深色沿用浅色的档位表、最透档不再换加强色、切主题不换样式表、取消不还原主题、主题名不归一、同义语那行写死颜色、同义语简释改用次要色、裸按钮不再垫底 |

## 八、没做的事

- **主题不影响系统对话框**。`QFileDialog` 在 Windows 上默认走原生框，深色主题下它仍是浅色。
  换成 Qt 版要丢掉「最近位置」「系统快捷方式」「OneDrive 入口」，代价大于收益；
  而且系统级 UI 与本程序不一致在用户预期之内。理由另见
  `docs/optimization-proposals.md` 的「我建议不要做的」。
- **不支持用户自定义配色**。自定义一套色板要同时保证 8 对文字 / 底色的对比度、深色浅色的
  最坏情况、以及半透明档位下的可读性——这不是「一个输入框加一个取色器」能兜住的，
  给错了我们还得负责。要加主题，走 `_ACCENTS` 加一条，让 selfcheck 去算。
