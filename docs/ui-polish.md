## 一、诊断：问题不在配色

结论先说：**「淡色 + 细边框 + 低饱和强调色」这条基底是成立的。**
五个界面的一致性、克制感、留白都在，没有需要推翻的东西。

问题集中在三处：

1. **层级** —— 工具栏六个按钮视觉权重完全相同；设置框「保存」与「取消」同权。
2. **对齐** —— 同义语的 chip 宽度随词长变化，右侧释义起始位置参差。
3. **提示可读性** —— 三类提示都是「一行长句直接铺在正文底色上」。

因此本方案**不改任何颜色常量**（`theme.py` 第 7–24 行全部保留），
只改「谁更显眼、边缘对不对齐、长句好不好读」。

## 二、前置约束：为什么尽量走 QSS

核过 `scripts/gui_smoke.py` 的 96 条断言，得到四条硬约束：

| 约束 | 位置 | 对方案的影响 |
|---|---|---|
| 只有 `btn_export` 断言了名称与提示 | 第 277–278、911–912 行 | 其余五个按钮可自由挂 `objectName` 换样式 |
| 提示断言的是**内容**：`_warn_label.text()` 须以「此词条不完整」开头，且含「重新查询」/「切到接口模式」/「离线词库」 | 第 141–158 行 | 只要不改文字，样式可以随便改 |
| 卡片删除走 `target_card.delete_button.click()` | 第 769、780 行 | `×` 必须仍在、仍可点 |
| `EXPECT` 是严格登记表，新增观测不登记即判失败 | 第 127–129 行 | 一旦新增控件，必须同步改判定谓词 |

**结论**：只改样式、不动文字与控件结构 → 96 条断言可以**一条不改**地保持绿。
故 P0 全部走 QSS；P1/P2 里只有「底部操作收拢」涉及一处布局代码。
这条不是省事，是**把回归面控制住**：改动面越小，「红了」才越能定位。

## 三、P0（收益最直接、风险最低）

### P0-1 提示条改为「柔色提示块」

**现状**：缺项 / 兜底 / 陈旧三类提示，都是 12px 棕色小字横跨整个面板、
直接铺在正文底色上。证据在 `preview_fallback.png`：

> 接口请求失败，以下内容来自本机离线词库　请求超时（30 秒）。可能是网络不稳定，或接口响应过慢。

这恰恰是**最需要用户读进去**的句子，现在最难读。而 `preview_incomplete.png` 里
还叠了两行（缺项 + 版本陈旧），更糊成一团。

**改法**（`app/ui/theme.py` 第 151 行，`QLabel#warn`）：

```css
QLabel#warn {
    font-size: 12px;
    color: #8A6224;              /* 必须与底色同时改，见下 */
    background: #FCF7EE;
    border: 1px solid #EADFC8;
    border-radius: 6px;
    padding: 7px 10px;
}
```

**为什么文字色必须同时改（实测对比度）**：

| 颜色 | 在白底 | 在提示块底 `#FCF7EE` |
|---|---|---|
| 当前 `#9A6B2F` | 4.65 | **4.36 ← 跌破 4.5** |
| 拟用 `#8A6224` | 5.45 | 5.11 |

只加底色、不改文字色，可读性**反而下降**。另外提示块底与白面板的对比只有
**1.07**（`#FCF7EE` vs `#FFFFFF`），几乎看不出边界——所以**描边不可省**，
靠 1px 边框定形，不能指望底色。

**唯一的技术风险已排除（实测）**：换行 `QLabel` 加 `padding` 会不会被裁高？
实测（真实平台、354 个字体族，`WA_DontShowOnScreen`）：

```
无内边距: sizeHint=16  heightForWidth=16  按字体度量需要=16
有内边距: sizeHint=32  heightForWidth=32  按字体度量需要=32
```

`heightForWidth()` 会把 `padding` 与 `border` 算进去，**不裁**。
所以这一项不需要任何额外的尺寸代码。

- **代价**：无，只有 5 行 QSS。
- **收益**：三类提示从「一行糊字」变成「一眼看到有块要说的话」。

### P0-2 工具栏分三级

**现状**（`app/ui/main_window.py` 第 211–220 行）：`查询 / 导入 / 导出 / 格式说明 /
备份 / 设置` 六个按钮**视觉权重完全相同**，只有查询挂了 `#primary`。
「设置」「备份」与「导入」长得一样重，视线没有落点。

**改法**：给后三个挂 `#bare`——主题里已有这个样式（`theme.py` 第 86–92 行：
无边框、灰字、悬停才显色）：

```python
self.btn_format_help.setObjectName("bare")
self.btn_backup.setObjectName("bare")
self.btn_settings.setObjectName("bare")
```

三级立刻成形：主操作（查询，实心）→ 常规（导入 / 导出，描边）→
次要（格式说明 / 备份 / 设置，无边框）。

- **约束**：`btn_export` 的名称与提示不能改（gui_smoke 断言），本项不动它。
- **风险**：零，纯 `objectName` 赋值，无结构改动。

### P0-3 卡片删除 × 再淡一档（按你的选择，走保守路线）

**现状**（`app/ui/widgets.py` 第 449–456 行）：每张卡右上角常驻一个 `×`，
五张卡就是一列五个噪点。删除是低频破坏性动作，不该与内容同等显眼。

**改法**（`theme.py` 第 125–136 行）：常驻色 `#B4B2A9` → `#C4C2B9`，悬停态不动。

**如实说清代价（实测对比度）**：

| 状态 | 颜色 | 在卡片白底上 |
|---|---|---|
| 现状 | `#B4B2A9` | 2.13 |
| 改后 | `#C4C2B9` | **1.79** |
| 悬停 | `#9A6B2F` on `#EFEFEC` | 4.03 |

WCAG 对非文字内容（图标、控件轮廓）的要求是 **3:1**。现状 2.13 **本来就没达标**，
降到 1.79 会更低。缓解措施有两条：

1. 保证悬停态回到 **4.03**（达标）；
2. 删除另有两处可达路径——卡片 tooltip（「从生词本中删除 X」）与详情区底部的
   「删除词条」按钮。

这是本方案里**唯一一项明确降低某项指标**的改动，所以单独标出来。
哪天觉得「1.79 太淡、找不着」，退回 `#B4B2A9` 即可，一行的事。

## 四、P1

### P1-1 同义语描述列对齐

**现状**（`widgets.py` 第 279–294 行）：chip 宽度随单词长度变化
（`pervasive` / `omnipresent` / `universal` 三者宽度各不相同），
右侧释义的起始位置因此参差不齐，同一个「同义语」区块里出现三级台阶。

**改法**：按当前词条的**最长同义词**统一算出列宽（派生，不写死常量——
写死常量时同义语一长、如 `conscientious`，chip 会撑出省略号）：

```python
# chip 的左右内边距是 11 + 11（theme.py 第 80 行 padding: 3px 11px）
_chip_w = max(
    (QFontMetrics(chip_font).horizontalAdvance(s.word) for s in entry.synonyms),
    default=0,
) + 22
```

再对每个 chip `setMinimumWidth(_chip_w)`。

- **上限保护**：`_chip_w` 超过面板宽度 40% 时退回自然宽度，
  否则一个长词会把整列释义挤到下一行。
- **代价**：需要拿一次 chip 的字体度量（样式表是全局的，`QApplication` 起来后即可量）。
- **收益**：同义语的「词」与「释义」成为两列，视线可以竖着扫。

### P1-2 底部操作右对齐收拢成一组（按你的选择）

**现状**（`widgets.py` 第 297–315 行）：`重新查询` 在最左、`删除词条` 在最右，
中间一个 `addStretch(1)` 撑开整片空白——两个按钮看起来互不相关。

**改法**：把 `addStretch(1)` 从「两个按钮之间」挪到「最前面」：

```python
row.addStretch(1)          # ← 整组推到右侧
row.addWidget(refresh)
row.addWidget(remove)      # 删除仍在最右，破坏性操作离手最近的一侧
```

顺带把 `删除词条` 的悬停色设为 `#9A6B2F`（与卡片 `×` 的悬停一致），
常驻仍是 `#8A8A86`——**不常驻报警，只在悬停时提示它是破坏性操作**。

- **风险**：低，一处布局顺序调整。gui_smoke 未断言详情区这个按钮的位置。

### P1-3 下拉框加宽

**现状**（`main_window.py` 第 236–240 行）：`setFixedWidth(86)`，
「最近」两个字加下拉箭头挤在 86px 里。

**改法**：`86 → 96`，并给 `QComboBox` 单独加 `padding-right: 22px`，给箭头留位。

## 六、独立项：过期预览图（Round 25 已修）

`preview_fallback.png` 曾是**过期图**：右下角状态栏仍写着
`已接入 · gpt-4o-mini · 失败时回落离线词库`，而出厂默认模型早已改成 `deepseek-chat`。
它当时与 `preview_settings.png` **自相矛盾**（后者已是 DeepSeek）。

**根因不是硬编码**——`scripts/screenshot.py` 里一直是
`config.get("model") or DEFAULT_CONFIG["model"]`，只是那张图生成于默认值变更**之前**。

**Round 25 已修**：本轮一次性重生成**全部八张**预览图（五张原有 + 三张新增的
背景图系列），而不再是一张张补：

```bash
QUILL_SHOT_KIND=fallback .venv/Scripts/python.exe scripts/screenshot.py preview_fallback.png
# 其余：不带 KIND 出主图；incomplete / settings / import 各出一张；
# background 出「开模糊」，background + QUILL_SHOT_BLUR=0 出「不模糊」
```

> 教训：**默认值变更没有跟着同步到产物**。只重生成「发现问题的那一张」是不够的——
> 同一次默认值变更会影响所有展示状态栏的图，漏掉任何一张都会留下自相矛盾的证据。
> 本轮改成**整批重生成**，把这类漏网从流程上堵掉。

## 七、明确不做

- **不引入渐变、阴影、动效**。项目基调是「淡 + 细」，这是刻意的选择，不是缺省。
- **不改任何既有颜色常量**（`BG / SURFACE / BORDER / TEXT / ACCENT` 等全部保留）。
  新增的只有 `#FCF7EE` / `#EADFC8` / `#8A6224`（提示块三件套）与 `DIVIDER`。
- **不改任何提示文案内容**——gui_smoke 断言它们的内容，改文案等于改接口。
- **不做深色模式**。真要做是另一个量级的工作（`theme.py` 得改成两套令牌 + 跟随系统），
  不该混在「美化」里顺手做。
- **不动 `×` 的常驻可见性**（按你的决策）。

| 项 | 要求 |
|---|---|
| `selfcheck` | **388 通过 / 0 失败** |
| `gui_smoke` | **115 通过 / 0 失败** |
| `http_smoke` / `lock_check` | 绿（54 / 5） |

**`gui_smoke` 是这套改动的主要防线**：它断言了提示文字内容、按钮名称、

所以**正常情况下它的既有 96 项应当一条不改**——新增的 12 项是本轮新功能的观测。

（唯一允许改断言的情形：确有必要改动结构，那就必须同步更新 `EXPECT` 里的判定谓词

> ——把 `EXPECT` 扩到 12 项新观测，让这条变异能被抓住。变异测试的价值就在这里：
> 它把「我以为有人守着」变成「确实有人守着」。

## 十、实施结果（Round 25 补记）

**P0 三项、P1 三项全部落地。** P2 只做了两项可低风险完成的：提示块的配色、
卡片 `×` 的淡化。其余 P2（例如设置框「保存 / 取消」同权）**未做**——本轮的主要
增量落在背景图上，P2 的边角改动留待下一轮，避免一次改太多、红了无法定位。

实施与方案有两处**偏离**，都记在这里备查：

| 方案原写法 | 实际实现 | 为什么 |
|---|---|---|
| 「不改任何既有颜色常量」，只新增提示块三件套与 `DIVIDER` | 另新增 `ICON_IDLE` | 卡片 `×` 要「再淡一档」，但**不能复用 `TEXT3`**——那个常量还管着占位文字与两处禁用态，改它会把那几处可读性一起拖下去 |
| 提示块沿用 `#9A6B2F` | 提示块文字色改为 `#8A6224` | 加了底色之后，`#9A6B2F` 在 `#FCF7EE` 上只有 4.36，跌破正文 4.5 的门槛——**只加底色、不动文字色，可读性反而下降**。新色 5.45 / 5.11 |

**关于验收条件表里的计数**：那张表是 Round 24 的快照（`selfcheck` 346 / `gui_smoke` 96）。
Round 25 在两套测试里新增了观测与断言，因此当前口径变为 `selfcheck` 388 / `gui_smoke` 115，
`mutation_check` 65 → 87、`ablation_check` 12 → 17。**这不是「改断言去迁就改动」**——
新增的全部是本轮新功能（背景图、界面层级）自己的观测，方案已明确「不许出现没登记的新观测」，
新增观测必须同时登记进 `EXPECT` 并给出判定谓词，这一点照做了。

**「`gui_smoke` 应当一条不改地保持全绿」这条预测没有完全成立**，原因值得记一句：
P0/P1 改动本身确实没有碰结构（`EXPECT` 里既有的判定谓词一条未改），
但本轮**新增**的背景图功能需要自己的观测，因此观测总数从 96 涨到 115。
把「既有断言一条不改」与「观测总数不变」区分开是要紧的：前者是纪律，后者只是巧合。

### 补记：方案里没预见到的一次返工（Round 25 二次）

方案把「面板转半透明」写成了达成条件，但没规定**透到什么程度**，实现时随手取了一个
保守的值（88%），并且把它写死在样式表里。结果是功能齐备、测试全绿，**用户看不见**：

> 「那你不还是没有做出自定义背景图的功能吗，只是加了个蒙版。」

量化之后才看清问题出在哪：窗口里 94.4% 的像素确实因背景图变了色，但那是**均值偏移**
——饱和纯红透上来只剩 `(252,229,226)`，面板上读不出「这里有一张图」。

返工做了三件事，都记进 `docs/window-background.md` 第四节：

1. 透出程度做成三档可选（含蓄 88% / 适中 72% / 明显 58%，默认适中），并把
   **「默认档不得是最含蓄那档」写成断言**——防它被悄悄改回去。
2. 三档的样式规则改为**由档位表生成**，不再手写。手写两遍时「改了常量忘了改规则」
   不报错、只是某一档静默地与另一档长得一样。
3. 判据从「有没有一条半透明规则」升级为「三档读出来的 alpha 必须依次变小」——
   档位没接到样式上时，面板会一直是同一个 alpha，看起来一切正常。

**教训（对这份方案同样适用）：「实现完了」与「用户用得上」是两件事。** 验收条件里
「预览图逐张肉眼核对」那条当时是照做的，但**核对的是「有没有画上去」，不是「看不看得见」**
——而这两件事在极淡的测试图上长得一模一样。样张不具代表性，结论就会指向错误的方向。

背景图的设计与取舍写在 `docs/window-background.md`，本文不重复。


## 十一、实施结果（Round 26 补记）

本轮做三件事：**① 把「自定义背景图」做到真正顺手；② 主题换色；③ 对主要功能提出
优化改进建议（只出方案，不动手）**。前两件改代码，第三件是 `docs/optimization-proposals.md`。

### 1. 背景图：从「能选一张」到「顺手换」

Round 25 让用户**能**配背景图，本轮补的是**换图这条路**：

| 新增 | 做法 |
|---|---|
| 拖拽添加 | 图片直接拖进窗口。**先弹一句问「要换成这张吗」**——拖动很容易误触，而误触的代价是覆盖掉正在用的那张 |
| 缩略图预览 | 设置里选好即出缩略图，所见即所得，不用先保存再看 |
| 最近使用 | 最近几张留在预览条上一键切回，不用每次重开文件对话框 |

### 2. 主题换色：六套，颜色只能有一份定义

靛蓝（默认）/ 松绿 / 赭石 / 绛紫 / 石墨 / 夜（深色）。设计写在 `docs/theming.md`，
这里只记**改的过程中暴露出来的东西**。

**（a）深色主题把一排中文简释整行变没了。** 同义语那一行原先是拼富文本、颜色写死成
`#1F1F1E` / `#8A8A86`——正好是**浅色主题**的 text / text2。深色主题的卡片底色是
`#24262A`，`#1F1F1E` 压在上面只有 **1.09:1**：不报错、不影响任何断言，只是让整排释义
消失。改成两个 QLabel（`#synGloss` / `#synNote`），颜色交样式表；修复后 night
12.35:1 / 6.35:1，ink 保持 16.50:1 / 3.47:1。

> 拆成两个控件而不是继续拼富文本，是因为**一个 QLabel 只有一个 `color`**：要让释义
> 比差异说明重一档，就只能往里塞字面颜色——而那正是缺陷的来源。

**（b）光把注释里的色值当代码，就等于禁止把坑写进文档。** 新增的「界面里不许有
字面颜色」扫描第一版报出的两处，**都是注释**：一处模板、三处 `widgets.py`——而那些注释
正在**解释**这个坑。判据加了精度：`tokenize` 去 Python 注释、正则去 `/* */`，
**字符串保留**（写死的颜色最常就出现在字符串里，那才是要抓的）。六种形态逐一自证。

**（c）一个颜色救不了两种背景。** 工具栏那三个无边框按钮与左栏底部的「共 N 条」
**不在面板里、也没有列表那样的轨道衬底**，字直接压在原图上。给它们换深色不行：
浅色主题的次要色压在一张中间调的图上，对比度趋近 1:1；换成深色，同一段文字落到图上
偏暗的那块又同样看不见。**所以是垫底，不是换色**——`_veil_rules` 的 targets 从 3 个
扩到 5 个（新增 `QPushButton#bare`、`QLabel#countLabel`，都用面板那一档的不透明度）。

> 「共 N 条」因此**必须有自己的 objectName**，不能复用 `#muted`：`#muted` 的实例大多
> 已经在受控表面上，给它垫底等于给面板里每个次要标签也垫一块白药丸。

**（d）深浅两套主题的最坏背景是相反的**——浅色怕背景图那块纯黑，深色怕纯白。于是
档位的**名**共用、**值**分家：`_VEIL_LIGHT = {soft:88, medium:72, bold:58}`、
`_VEIL_DARK = {soft:96, medium:84, bold:72}`。

### 7. 收尾验证里揪出的两处**工具自身**的缺陷

这一轮真正的收获不在主题，在收尾。两次全链跑各暴露一处，**两处都属于「工具在说假话」**。

**（a）消融报表把 A2 的话说给了 A20 / A21 / A22。** 报表末尾的「要点补充」按
`name.startswith("A2")` 挑条目——字符串前缀把 **A20 / A21 / A22 一起命中**，于是那三项
被套上了只对 A2 成立的结论：「命中条数前后一致，变的是**耗时**」。**那是假话**：它们变的
是用户看得见的东西。**假话读起来最通顺，所以没人会去怀疑。**

修法：判据改为按编号**精确相等**（`item_id()`），要说的话改成**表驱动**（`_EXTRA_NOTES`
按编号挂，没挂就不说），再加两条**能失败**的静态校验——编号不许重复、「要点补充」不许挂在
清单里没有的编号上。

> 我先写的是更硬的一条守卫：**禁止编号互为前缀**。自证时它自己翻了车——现用编号就是
> A1…A22，`A2` **本来就是** `A20` 的前缀，这条守卫会把一份**能用的清单直接判死**。
> **为了让守卫成立去重命名一堆在用的标识符，那是为做而做。** 换成表驱动 + 唯一性校验。
> 这与 `clean_temp.py` 的前缀表是**同一个家族**：前缀判据要么只留一份定义，要么改精确匹配。

**（b）一条变异的「CAUGHT\*」其实是变异自己把源码改坏了。** 我写的锚点缩进是 8 空格，
真实代码是 **12 空格**（在 `if syn.gloss_zh:` 里），而 `text.count(old) == 1` **照样通过**
——**替换是按子串做的，多出来的那 4 个空格还在文件里**。替换后 `setText` 落在 8 空格、
同一块其余行在 12 空格，文件直接 `IndentationError`；测试在**导入阶段就死**，报表写
「CAUGHT\*（代码崩溃）」，看着像「测到了」，其实是**变异把源码改坏了**，那条字面颜色断言
根本没轮到出场。

修法：修锚点缩进（12 空格），并给**变异与消融都加上**「改完的文件必须还能 `ast.parse`」——
不通过就报 `[BAD]`，明确写「这是变异/消融写错了，不是测试没抓住」。**挡在跑测试之前**，
省一次误判，也省一整轮等待。

**（c）还有一条 MISSED：「最近使用不去重」。** 观测是「这张图**在不在**列表里」——
去掉去重之后那张图**照样在**（只是出现了两次）。**成员判定天生分不出「一个」和「两个」**，
所以这不是实现有缺口，是**判据有盲区**。补的观测改成数**个数**：
`同一张图重复使用不占两个位置 → (1, 1)`。

> 三条合起来是同一条教训的三种形态：**判据的「形状」决定了它能看见什么。**
> 「在不在」看不见重复，「前缀」看得见太多，「能匹配上」不等于「对得齐」。
> 变异/消融跑出 MISSED 或 CAUGHT\* 时，先分辨是**实现有缺口**、**判据有盲区**、
> 还是**变异自己写错了**——三者的修法完全不同，而它们的输出长得差不多。

### 8. 前一轮那两条收尾修复（同一家族，第十次兑现）

**（a）`Lexicon.exe --selfcheck` 每跑一次就在系统盘留一个目录。**

`run.py::run_selfcheck()` 用 `tempfile.mkdtemp(prefix="lexicon_selfcheck_")` 建临时
数据目录（里面 6 个 SQLite 文件、约 1.5 MB），**建了却从不删**。这段代码在**打包
产物**里，所以每跑一次自检就多留一个——不报错、不影响任何断言，只是让系统盘
悄悄涨。**这正是铁律 12 说的那种泄漏**（本项目踩过同款：6 处 `mkdtemp` 不清理 →
3763 个目录 / 2.6 GB，最后以 `ENOSPC` 的形式爆发，看起来像「工具坏了」）。

修法：`atexit.register(_cleanup_home, home)`，清理函数**重试 + `gc.collect()`**，
仍失败**打印警告**——`ignore_errors=True` 会把「删干净了」和「静默没删」变成同一件事
（截图上踩过一次，静默漏掉 8 个装着 `lexicon.db` 的目录）。实测：跑前 0 个、跑后
0 个、自检 24/24。

**（b）残留检查的前缀表被抄成了第二份，而且更窄。**

`selfcheck` 里 `_verify_no_temp_leftovers()` 自己列了 6 个前缀，而
`clean_temp.PREFIXES` 有 14 个——**少了 `lexicon_shot_*` / `lexicon_lock_*` /
`lexicon_ablate_*` / `lexicon_probe_*` / `lexicon_gui_*` / `lexicon_export_*` /
`lexicon_v1_*` / `lexicon_userdict_*` 八个**。后果不是「少报几条」，是**整整一类
泄漏不在视野里**：那个 10 月 11 日的 `lexicon_selfcheck_*` 在系统临时目录里躺了
一整天、跑了几十轮检查，**没有任何一条断言提到过它**（而且它连 `clean_temp` 那张表
也没登记——**两张表都没有它**）。

修法三件：
1. `selfcheck` 改为 `from clean_temp import PREFIXES`——**前缀表只留一份定义**。
2. `clean_temp.PREFIXES` 补上 `lexicon_selfcheck_*`。
3. 加一条**能失败**的自证 `_selftest_leftover_prefixes()`：建一个 `lexicon_shot_*`
   前缀的临时目录（**旧窄表认不出它**），看残留检查报不报。实测：真表下 PASS、
   换成修复前那份窄表就报 FAIL——它不是恒真断言。

> 这与 `ablation_check` 早先那次是**同一个坑的第二处**（那边注释里写着「探针的清理
> 只认 `lexicon_ablate_*`，于是另外三个子套件的泄漏完全不在视野里」）。**同一个教训
> 在一个仓库里出现两次、都由前缀判据引起**——所以现在前缀只许有一份定义。

**（c）顺带修掉一句自相矛盾的报表**：消融基线的 `selfcheck` 打出「退出码 1  全绿」。
不是 bug，是两件事被压成一行——`selfcheck` **先打完汇总行**、再在 `atexit` 之后检查
临时目录残留，有残留就 `return 1`。修法是把第二件事的名字写出来
（`（无失败项，但退出码非零）`），别让人去猜。

## 十二、实施结果（Round 27 补记）

这一轮做的不是"美化"而是**补功能入口**（详见 `docs/optimization-proposals.md`
的实施回执）。界面侧新增了四处控件，各有它自己的坑：

### 详情区多了一行「标签」输入框

与备注走**同一条自动保存通道**（600ms 防抖 → `_flush_edits()`），但两条待写值
**各自记一份**：用户完全可能改了备注又改标签，两者都在防抖窗口里等着落库。

这里有个真实缺陷形态值得记下来：`_flush_edits()` 原先叫 `_flush_note()`，只处理
备注。接标签时如果沿用"复用同一份 `entry` 对象"的写法，两次 `upsert()` 里后写的
那次会把先写的覆盖回去——**两条都报「已保存」，其中一条静默消失**。现在的写法是
每条各自 `get_by_id()` 重读一次再写。代价是一次 SELECT，换来的是"谁先写谁后写都不丢"。

`join_tags()` 把输入归一成单空格再落库——**这是全部三处消费方共用的唯一一份定义**。
不归一的话，"按标签筛选"就只能退回 `LIKE '%考研%'`，而它一定会在"某个标签是另一个
的前缀"时出错。

### 左栏多了一排「标签」筛选

下拉里列出库里全部标签及各自条数。**整份重建，不做增量维护**：标签会因为三条互不
相干的路径变化（详情区编辑、导入带回、删除词条），增量维护等于在这三处各写一份同步
逻辑——漏掉任何一处都只是"下拉里少一个标签"，不报错，而且很久都不会被发现。
重建时必须 `blockSignals`，否则 `setCurrentIndex` 会再走一次 `_reload_list`，
"重建下拉"变成"重建中又重建一遍"，最外那一次用的是已经过期的标签清单。

正在筛的那个标签**消失**时，筛选要跟着撤销：留着它，列表会永远空着而下拉显示
「全部标签」——用户看到的是一份"明明是全部却什么都没有"的列表。

### 状态栏多了一个「撤销删除」

**必须放永久区**（`addPermanentWidget`）。`QStatusBar.showMessage` 会盖住普通区
（`addWidget`）的控件，而删除之后**恰恰必有一条提示消息**——放错区的话，这个按钮
永远不会出现，功能等于没有。

样式写的是 `QPushButton#statusButton`，**不能挂 `#bare`**：那条规则带背景色，会在
状态栏里贴出一块方块。

### 它没有变的那些东西

「淡 + 细」这条基调一寸没动：新控件全部沿用既有的 `#input` / `#bare` / `#muted`
样式，没有引入新的颜色、渐变或阴影。新增的样式只有上面那一条状态栏按钮——
因为它所处的容器（状态栏）此前没有按钮，`#bare` 的背景色在那里是错的。

## 十三、实施结果（Round 28 补记）

这一轮加的是**一个内容区块**（固定搭配）与**第二个集合**（词组收藏），界面侧
新增了五个控件。五个控件里有**两个**属于「忘了登记就静默看不见」那一类。

### 右栏：固定搭配区

一条搭配 = 词组 + 中文简释 + 「收藏」按钮（同一行），下面配**它自己的**例句与翻译。

例句必须跟着搭配走，不能并进上面那个例句区：`be in charge of` 与 `take charge of`
的差别只有各自的例句说得清。把搭配列成一张干巴巴的词组表，等于把最该看的东西
（怎么用）丢了。

左侧缩进 2 格，与「英 / 中」两行的正文起点对齐——搭配是词条内容的一部分，
不该看起来像另一个层级的东西。

### 忘了登记就看不见的两处

1. **`QLabel#collGloss` 必须进 `theme._STRONG_TEXT`。** 那张表是「最透那一档下
   要加深的次要文字」的登记表。漏一个的表现是「只有搭配的中文简释看不清」——
   **不报错**，而用户会以为那条搭配没有简释。`selfcheck` 里有一条断言直接问
   「`("QLabel#collGloss", "text2_strong")` 在不在表里」，`mutation_check` 里
   也有一条变异把它移出去。
2. **`QPushButton#mode` 必须进「直接压在原图上的控件」表。** 左栏那对切换按钮
   既不在面板里，也没有列表那样的轨道衬底——配了背景图之后字直接压在**原图**上。
   给它们垫底而不是换文字色，理由是**图片的明暗未知**（浅色主题的次要文字
   `#8A8A86` 压在中间调的图上对比度趋近 1:1）。不透明度沿用面板那一档：同一屏
   里两处文字的可读性该由同一个规则决定。

这两处都不是「新样式」，而是**新控件要接进已有的两张登记表**。加控件时最容易
漏的就是这一步，而漏掉的两边都不报错。

### 词组详情刻意**不复用** `show_entry`

`show_phrase` 与 `show_entry` 是两条路。`show_entry` 会建备注与标签两个
输入框，而它们发信号时带的是**词条的 id**——词组与词条是两张各自从 1 发号的表，
同一个数字在两边是两条毫不相干的数据。复用等于把「改这个词组的备注」接到
「改那个词条的备注」上，而两边都会显示成功。

所以词组详情里没有备注框、没有标签框，只有简释、例句与一个「移出词组收藏」按钮。

### 左栏：生词本 / 词组收藏

一对 `#mode` 按钮，条数跟着每次重载重算而不做增量维护（它会因为查词、批量查词、
导入、删除、撤销、收藏词组**六条互不相干的路径**变化；增量维护等于在六处各写
一份同步逻辑，漏一处只是「数字不对」）。切到词组模式时「标签」那一行整行隐藏——
词组没有标签，留着一个只有「全部标签」一项的下拉就是在占位。

### 卡片复用，删到哪张表必须分派

词组的卡片就是 `EntryCard`（走 `Phrase.to_entry()` 适配）——**这是有意的**：
卡片、`_list_text`、六种导出、格式说明样例全都只认 `Entry` 一种形态，为词组
再写一套就是同一件事的第二份定义。

但 `deleteRequested` 的接线必须分岔（`_request_phrase_delete` / `_request_delete`）：
两张表的行号各自从 1 发号，拿词组的 id 去删词条会**安静地删掉另一个词**。

### 它没有变的那些东西

「淡 + 细」一寸没动：搭配区只加了三条 QSS 规则（`#collPhrase` / `#collGloss` /
`#collExample`），用的全是**已有的颜色变量**（`$text` / `$text2`），没有引入新的
颜色、渐变或阴影；「收藏」按钮直接复用 `#chip`。`selfcheck` 里那条「卡片保持
不透明」的反向断言也照旧成立——搭配区在面板内部，面板半透明时它跟着面板走，
不额外开洞。

## 十四、实施结果（Round 29 补记）

这一轮不是「再加点美化」，而是把上一轮体检列出的**四处量化缺陷**修掉。
四项都有实测数字，不是观感描述。

### P0-1 `QLabel#chip` 是一条约等于死规则的合规文本

`#chip` 的两处使用点（同义语 chip、搭配区「收藏」按钮）**都是 `QPushButton`**
（`widgets.py:576` / `widgets.py:357`），而样式表写的是 `QLabel#chip`。Qt 不会
为此报任何错：样式表构造成功、加载成功、零警告，那两处只是静静地落回通用按钮
样式（白底 + 描边 + 控件圆角）——「同义语 chip 是个淡色胶囊」这件事从来没有
发生过。实测该控件底色 `#ffffff`，而不是设计的 `#eef3fa`。

改成 `QPushButton#chip` 后实测 `#eef3fa`。

> 这条的意义不在那几行 QSS，在**判据**：上一轮的静态扫描只问「`#{name}` 在不在
> 样式表里」，于是把 `chip` 判成了「已覆盖」。**选择器前缀的控件类必须与使用处
> 一起核**——现在 `selfcheck` 两侧都核：样式表里是 `QPushButton#chip`（且不许有
> `QLabel#chip`），`widgets.py` 里 `setObjectName("chip")` 上一行确实是
> `QPushButton(`。`gui_smoke` 再加一条读像素的观测。

### P0-2 / P0-3 交互状态此前**一条规则都没有**

`:checked` 0 条 → 左栏「生词本 / 词组收藏」是 `setCheckable + setAutoExclusive`，
选中与未选中**四角像素完全相同**（实测都是 `#ffffff`），用户在界面上看不出自己
在哪个集合里。`:pressed` 0 条 → 按下去与不按长得一模一样。

补完后的实测：选中态 `#eef3fa`、未选中态 `#ffffff`（两条一起读，差值才是判据）。
按下态给通用按钮、主按钮、裸按钮、chip、卡片 ×、状态栏按钮各一条。

一处细节值得记：`QPushButton#primary:pressed` **必须单独写**。`QPushButton#primary`
比 `QPushButton:pressed` 更具体，通用那条压不到它的底色上——写了不生效，且不报错。

配背景图时，选中态的底还要走一档半透明，所以 `_veil_rules` 的 targets 多了
`QPushButton#mode:checked`（垫 `accent_soft` 而不是面板色）；不这么做的话，最透
那一档会把选中态统一刷成面板色，选中与未选中又变得一模一样——**刚修好的缺陷会
在「配了背景图」这个条件下复发**。新目标一律插在 `("QPushButton#mode", …)` **之前**：
变异脚本有一条锚点是拿「它 + 收尾括号」定位的，插在后面会让那条变异找不到锚点。

### P1 对比度：一个门槛放宽，一个白名单跟上

| 令牌 | 旧值 | 白底 | 新值 | 白底 | 窗口底 |
|---|---|---|---|---|---|
| `text2` | `#8A8A86` | 3.47 | `#6E6E6A` | **5.12** | 4.94 |
| `text3` | `#B6B6B1` | 2.04 | `#91918C` | **3.13** | 3.02 |

`text2` 承担的全是**真内容**（音标、词性、卡片中文简释、同义语差异说明、搭配
简释、状态栏），所以它进的是 `≥4.5:1` 那一组，底色取**面板与窗口底两个**——
只验一个等于放掉一半。

`text3` 只守 **3:1**，这一步要写明白理由：它只允许用于**占位符**与**禁用态**
（`#placeholder`、`QPushButton:disabled`），WCAG 1.4.3 对禁用控件明确豁免，占位符
低于正文对比度也是各平台的通行做法。但旧值 2.04:1 不是「淡」，是「看着费劲」。

> **门槛松的那一半，靠用途白名单兜住。** `selfcheck` 里新增一条：把模板里的
> `/* */` 注释剔掉之后，凡是含 `$text3` 的规则块，其选择器必须落在
> `{QLabel#placeholder, QPushButton:disabled}` 里。哪天有人把它拿去当真内容用，
> 这里当场报红。

连带两处「真内容被错放在占位色上」的都归了位：`#section`（详情区的「英 / 中 /
例句 / 固定搭配」）与 `#reviewHint`（复习页那句「先回想一下这个词的意思」）都改挂
`$text2`。`#section` 在最透档的加强色也跟着从 `text3_strong` 换成 `text2_strong`
——**加强色必须跟着基础色走**，否则会出现「平时是次要色、最透档反而换成更浅的
占位色」。

顺带把 `#section` 与 `#sectionTitle` 合并成**一条**规则（它们两行一模一样，
分属详情区与导出对话框，但样式只有一处定义）。

**没动的一项，如实记**：卡片 `×` 的常驻色 `#C4C2B9` 在卡片白底上只有 1.79:1，
低于非文字内容的 3:1。这是 Round 25 用户明确拍板「保持常驻但再淡一档」的结果，
本轮不动它，也不假装它达标——它的缓解措施有两条：悬停态 4.03:1 达标；删除另有
卡片 tooltip 与详情区「删除词条」两条可达路径。

### P2 圆角 token 化 / 内联样式收口 / 一处漏登记的控件

1. **圆角**：四个语义（容器 8 / 控件 6 / 胶囊 9 / 把手 5）原先散在模板里写成
   四个字面数字，谁也说不清「这个 6 与那个 8 是两回事还是写岔了」。改成
   `$radius_container` 等四个 token，与颜色**走同一条取值路径**（并进调色板，
   登记进 `_TEMPLATE_KEYS`）。新增一条能失败的静态校验：模板里凡出现
   `border-radius:` 的行，值必须是 `$` 开头的 token。
   值一律带 `px`：`$radius_controlpx` 会被当成一个不存在的键名留在原处，Qt 解析
   失败后静默退回直角。
2. **内联样式收口**：欢迎页与复习页的字体规则（`#welcomeTitle` / `#reviewLemma` /
   `#reviewHint` …）原先在各自文件里拼 `setStyleSheet`。颜色虽取自调色板、没有
   字面值，但「标题多大、次要文字什么色」仍是两处定义。收进 `theme.py` 模板后，
   它们同时受「不许字面颜色」与「每套主题都必须补齐模板全部键」两条断言约束。
   两个对话框仍然自持样式（构造时 `setStyleSheet(stylesheet(tid))`），
   「不依赖 QApplication 全局样式表」这条性质照旧。新增断言：这两个文件里
   **不许再出现** `font-size:` / `font-weight:` / `padding:` / `border-radius:`。
3. **`#review` 从未登记**：左栏「待复习 N」此前**一个样式规则都没有**，落回通用
   按钮后在一排淡色元素里比列表还抢眼。补成无边框强调色文字按钮，并**登记进
   `_veil_rules`**——它同样直接压在原图上，不垫底的话最透档下只有 1.69:1。
   这正是本项目反复强调的那件事：**新控件要接进已有的两张登记表**（加强色表 /
   垫底表），漏掉的两边都不报错。
   顺带钉了一条更硬的判据：垫底表里七个「自己没表面」的控件按**名字**逐个核
   （判据带 ` {` 后缀——`QPushButton#mode` 是 `QPushButton#mode:checked` 的前缀，
   不带后缀的话删掉未选中那条照样判过）。

### 自证：第一次跑出来的 9/9 全是假的

新断言照例逐条自证能失败（把源码改回修复前的样子，看它报不报红）。第一版自证
脚本跑出 **9/9 被抓住**，但那是**假的**——每条的失败列表第一条都是：

```
FAIL  文本文件行尾统一为 LF  app\ui\theme.py
```

原因：`Path.write_text` 在 Windows 上默认把 `\n` 翻成 `\r\n`，于是每次变异都
捎带把整个文件的行尾改坏，`selfcheck` 里那条「行尾统一为 LF」连报 3 条红，
**退出码非零达成，看起来每次都抓住了**——抓到的根本不是我要验的那条断言。
而还原时同样走 `write_text`，读回来又被通用换行转换「修好」，所以连
「还原后逐字节核对」这一关也静默通过了。

修法两条，都写进了 `scripts/prove_checks.py` 的文件头：

1. **读写一律走字节**（`read_bytes` / `write_bytes`），行尾不再被实现细节改写；
2. **判据从「退出码非零」改成「基线干净 + 这条变异的预期断言名出现在失败列表里」**。
   先把基线跑一遍（应为 0 失败），再逐条比。否则任何一条无关的红都能把「没抓住」
   粉饰成「抓住了」。

改完重跑：**9/9 真被抓住**，每条都打印出命中的那条断言行。

> 这与第十一节那次「消融报表把 A2 的话说给 A20/A21/A22」是同一个家族：
> **判据的形状决定了它能看见什么，也决定了它能掩盖什么。** 退出码只回答
> 「有没有红」，不回答「红的是不是我要验的那条」。
