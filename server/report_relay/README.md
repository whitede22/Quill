# 使用报告中转函数

Quill 客户端点「提交报告」时，把 JSON 发到这个函数，函数用 SMTP 把摘要与附件发到收件邮箱。
客户端不持有任何发信凭据。

## 环境变量

| 名称 | 说明 |
|---|---|
| `SMTP_HOST` | 默认 `smtp.qq.com`，可以不填 |
| `SMTP_PORT` | 默认 `465`，SSL |
| `SMTP_USER` | 发件邮箱，例如 `someone@qq.com` |
| `SMTP_PASS` | 邮箱授权码，在邮箱设置里开启 SMTP 后生成，不是登录密码 |
| `MAIL_TO` | 收件邮箱，多个用逗号分隔 |
| `REPORT_KEY` | 客户端带来的共享密钥，自定义一串随机字符 |

## 部署

1. 腾讯云控制台进入「云函数」，新建函数，运行环境选 Python 3.10，选「从头开始」。
2. 函数入口填 `main.main_handler`，把本目录的 `main.py` 内容贴进在线编辑器。
3. 执行超时改为 30 秒，内存 128 MB 够用。
4. 在函数配置里添加上面六项环境变量。
5. 开启「函数 URL」，鉴权方式选不鉴权。函数自己校验 `REPORT_KEY`，腾讯云那层鉴权会让桌面客户端多一次签名流程，没有必要。
6. 复制函数 URL，填进客户端的 `app/core/report.py` 里 `DEFAULT_ENDPOINT`。

## 接口

请求：

```
POST <函数 URL>
X-Report-Key: <REPORT_KEY>
Content-Type: application/json

{"report": {...}, "summary": ["...", "..."]}
```

响应 200 表示邮件已经交给 SMTP 服务器。其余状态码含义：

| 状态 | 含义 |
|---|---|
| 400 | 请求结构不对 |
| 401 | 密钥不符 |
| 405 | 不是 POST |
| 413 | 超过 256 KB |
| 429 | 同一 IP 十分钟内超过三次 |
| 502 | SMTP 发信失败 |

## 已知局限

限流记在函数实例的内存里，多个实例之间不共享，冷启动会清零。它挡的是随手刷接口的人，挡不住有意的持续调用。真正起作用的防线是密钥，改动密钥要同时更新客户端与函数。

邮件是否送达收件箱还取决于发件邮箱的信誉。QQ 邮箱对同一账号每天的发信量有上限，报告这种量级碰不到，但如果这个邮箱还兼作他用就要留意。
